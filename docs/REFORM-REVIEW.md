# 개편 판단과 검토 안내

## 판단

현재의 관리 화면과 Nginx/ModSecurity → Fluent Bit → Kafka → 저장소 구조는 유지할 가치가 있다. 먼저 보완할 부분은 외형보다 **인증, 저장 성공의 의미, 오류 표시, 실행 설정의 일치**다. UI에서 보이는 성공과 실제 서버 상태가 달랐고, 개별 모듈의 빌드 성공만으로는 서비스 간 연결을 확인할 수 없었다.

전면 재작성이나 새로운 서비스 도입보다 기존 경계를 정리하는 방식으로 첫 PR을 구성했다. 새 라이브러리를 추가하지 않고 현재 Java·Next.js·Go·Python 모듈을 사용한다.

## 우선순위와 변경

| 우선순위 | 확인한 문제와 영향 | 이번 변경 | 남은 경계 |
| --- | --- | --- | --- |
| P0 | dashboard API의 인증 공백, OAuth state 검증 부족 | 공유 JWT 검증, state 서명·만료·재사용 검사, 서버 HttpOnly 쿠키 | 운영 사용자/역할 권한 정책은 별도 |
| P0 | 인코딩된 URL이 인증 필터를 우회 | 실제 HTTP 재현을 기준으로 경로 검사와 회귀 테스트 보완 | 전체 침투 테스트를 수행한 것은 아님 |
| P0 | 필수 저장 실패 후 Kafka 오프셋이 진행할 수 있음 | 저장 성공 후 커밋, 실패 배치 보존, 이미 저장된 배치의 커밋 재시도 분리 | 프로세스 중단·재처리 시 중복 가능 |
| P1 | 규칙 변경/배포 실패를 화면에서 성공으로 표시 | 초안 CRUD를 파일에 저장하고 오류 전달, 배포 `501` | 실제 ModSecurity 검증·reload·롤백은 미구현 |
| P1 | 임의 경고, 가짜 가동률·정상 상태, 조회 실패의 0 처리 | 조회 실패와 빈 결과 구분, 확인되지 않은 상태 표시 | 실제 경고 스트림 생산자 미연결 |
| P1 | 화면별 API 모델과 경로 불일치 | 같은 출처 서버 프록시, 규칙 모델 통일, 빈 DELETE 응답 처리 | 초안 저장은 단일 dashboard 프로세스용 |
| P1 | 수집 이벤트와 저장/조회 스키마 불일치 | 중첩 분류, Elasticsearch 필드, ClickHouse 추가 컬럼, 이벤트 식별 정렬 | 기존 인덱스/볼륨의 마이그레이션은 자동 적용하지 않음 |
| P1 | Compose/Kubernetes의 키·토큰·이미지·ConfigMap 연결 불일치 | 설정 생성 경로 통합, 환경 변수·Secret·볼륨 연결, 준비 실패 반환 | 실제 컨테이너/클러스터 구동 검증 필요 |
| P2 | 중복 규칙 편집 구현과 레거시 데모 경로 | 사용하지 않는 구현 제거, 공통 화면으로 연결 | 대규모 화면 재설계는 하지 않음 |
| P2 | 모바일 헤더가 화면 너비를 초과 | 기존 메뉴를 유지하면서 좁은 화면의 배치 보완 | 모든 기기·브라우저 조합을 검증한 것은 아님 |
| P2 | README의 기능·성능 주장이 실제 근거와 불일치 | 현재 지원 범위와 검증 한계를 명시 | 부하 측정 후 운영 SLO를 정해야 함 |

P0는 인증/데이터 보존, P1은 기능 신뢰성, P2는 유지보수와 사용성 기준이다. 코드와 로컬 재현에 근거한 판단이며 운영 환경의 발생 빈도나 피해 규모를 측정한 순위는 아니다.

## 검토 순서

1. `docs/REFORM-PLAN.md`와 `docs/CUSTOM-RULES.md`에서 초안 저장과 실제 WAF 적용의 경계를 확인한다.
2. backend의 JWT/state, 인증 필터, 초안 저장과 회귀 테스트를 검토한다.
3. frontend 서버 프록시와 실제 UI의 성공·실패 표시를 함께 확인한다.
4. Go/Python 소비자의 저장 → 커밋 순서, 재처리와 중복 정책을 확인한다.
5. 생성 스크립트와 원본 설정을 검토한 뒤 Compose/Kubernetes 결과를 확인한다. 생성된 `02-configmaps-only.yaml`만 단독 수정하지 않는다.

네 구현 브랜치는 범위별 검토를 위해 유지한다. 통합 PR은 교차 계약을 함께 검토하기 위한 것이며 병합·운영 배포는 수행하지 않는다.

## 검증의 범위

- 단위/회귀 테스트: JWT와 OAuth state, 초안 저장 실패·재시작, 데이터 조회 오류, 프록시/SSE와 UI 계약, 소비자 오프셋 및 배치 보존.
- 정적/빌드 검사: Java 빌드, 프런트엔드 lint·typecheck·프로덕션 빌드, Go test·vet, Python 테스트, Compose 파싱, shell 문법, Kubernetes YAML 및 설정 참조.
- 로컬 HTTP 확인: 실제 Java 서버와 Next 서버 사이의 인증 거절, 변경 요청의 출처 확인, 초안 CRUD, `204` 삭제, 배포 `501`, 조회 장애 응답. OAuth 시작/state 거절까지 확인하며 실제 Google 계정의 인증 코드는 교환하지 않는다.
- 브라우저 확인: 모의 통계 응답을 이용한 데스크톱/모바일 화면 확인. 화면 형태 확인용이며 데이터 수집 성공의 증거는 아니다.

구체적인 최종 통과 결과는 PR 본문과 CI에서 확인한다. Docker 데몬과 Kubernetes 통합 환경을 사용할 수 없어 이미지 빌드, 전체 서비스 연결, ModSecurity 공격 차단, 클러스터 적용은 검증하지 못했다.

## 후속 개편 순서

1. **통합 환경 검증과 기존 의존성 업데이트**: 실제 데이터가 WAF에서 저장소까지 도착하는지, 재시작 시 재처리가 되는지 먼저 확인한다. 이번 npm 설치 감사에서는 기존 취약점 19건이 보고되었다.
2. **실제 규칙 배포 경로**: 초안 검증, 적용 버전, Nginx 구문 검사, reload 확인, 실패 복구를 한 작업 단위로 구현한다.
3. **운영 권한과 저장소**: 변경 주체 감사 기록, 운영자 권한, 다중 인스턴스 저장, OAuth state 재사용 방지의 인스턴스 간 공유를 설계한다.
4. **측정과 비용**: InfluxDB 이벤트 식별 태그의 시리즈 수, Kafka 지연, ClickHouse 중복/보관 정책을 실제 부하로 측정한다.

기능을 더 늘리기 전에 위 항목으로 현재 기능의 신뢰성을 확보하는 것이 이 코드베이스에 적합한 개편 방향이다.
